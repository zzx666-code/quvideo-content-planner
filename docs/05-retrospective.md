# 工程复盘

## 最难的问题

最难的部分是区分“工作流能跑完”和“模型根据工具结果作出正确调整”。离线策略全部通过后，真实模型仍在更换费用表时提前停止：初稿费用 12、标准方案也超预算，但仍有费用 4 的简洁图文方案。模型没有继续选择，程序正确返回未完成。

通过保留该失败样例、编写先失败的回归测试，再补充最多一次完成条件反馈，运行时能够指出尚未完成及已有可行候选，同时保持下一步工具和档位由模型决定。程序负责可验证的约束，模型负责业务动作选择，二者分工清楚才能解释结果。

## 实际收获

1. pi Agent Core 已具备循环、工具结果回传、事件、steering 和中止能力，业务项目应复用这些接口，把精力放在数据、约束和状态上。
2. 真实模型测试不能由确定性替身代替。改变费用表和注入错误比只跑一条正常流程更容易发现缺陷。
3. 最终状态必须基于保存回执；预算与时间必须用数据表重新计算。旧估算、模型文本或某一步成功都不能充当完成证据。
4. 失败历史和可复用结果应分开保留。续跑使用结构化素材、稿件和估算，而不是依赖包含内部思维的原始会话转储。
5. 可复现不等于输出逐字一致。锁定依赖、固定场景时钟、保存源文件指纹和实际 Trace，才能比较模型在相同约束下的行为。
